Abstract

Image-based reconstruction connects camera geometry, scene representation and image formation. This report describes the MakeWorlds workflow at the system level, from input photographs to a delivered Gaussian scene. It introduces the public concepts behind the representation and explains how visual comparisons and numerical evaluation answer different questions. Experiments on Train, Dr Johnson and Playroom report image quality and cross-platform variation for a fixed candidate, with the published 3DGS values as reference points.

Topics Image-based reconstruction · Gaussian splatting · Camera estimation · Cross-platform evaluation

01 / SYSTEM OVERVIEW

A connected reconstruction workflow

The task is to recover a scene that can explain photographs taken from different positions. A useful result depends on both the estimated cameras and the learned scene: their relationship determines how a three-dimensional model becomes an image.

Geometry before appearance

Camera estimation establishes the viewpoint associated with each image. Intrinsics describe the camera projection, while extrinsics relate the camera to scene coordinates. Structure-from-Motion provides this geometric context; the COLMAP documentation describes the underlying reconstruction problem.

A concrete output to inspect

MakeWorlds carries the reconstruction through to a Gaussian PLY asset. The visual study pairs images from the delivered scene with their reference photographs. This gives readers an observable result alongside the numerical summary.

02 / TECHNICAL BACKGROUND

Representing a scene with Gaussians

A Gaussian scene uses spatial primitives with position, oriented extent, opacity and appearance. These primitives exist in a shared three-dimensional coordinate system and can be projected into a chosen camera. This representation is established in the 3D Gaussian Splatting paper.

During scene fitting, rendered views are compared with observed images. Changing the scene parameters changes the rendered images, allowing image disagreement to guide optimization. The expression alongside gives the standard spatial Gaussian used to describe the primitive in that literature.

04 / EXPERIMENTAL DESIGN

What is being measured?

Camera estimation, scene quality and platform variation address different parts of the reconstruction problem.

Image comparison and view selection

Each image pair uses one evaluated camera viewpoint. The display views highlight overall shape, an oblique overview and side texture. Numerical summaries instead aggregate the evaluated test views, so they do not depend on which images appear in the visual study.

Two evaluation questions

The paper-comparison table places the recorded PSNR, SSIM and LPIPS beside published per-scene reference values. MakeWorlds estimates its own cameras, so these figures describe an end-to-end reconstruction comparison. The separate cross-platform record asks how far the test-set means vary across the three platform runs.

Why the two tables are separate

The cross-platform spread is computed within its own evaluation protocol. It should not be reconstructed by subtracting values from the paper-comparison table. Keeping the protocols separate preserves what each measurement actually describes.

Reading the evidence

Image-quality metrics characterize this set of reconstructions. Platform spread characterizes agreement of the measured image-quality means; it is not a frame-rate measurement or a claim of byte-identical models. The data files retain the candidate and run identifiers so each row can be traced to its recorded evaluation.
